# Blank recipes

Blank recipes use the existing `recipes.source_type` value `blank`; no migration is required. POST `/households/{id}/recipe-blank` authenticates household membership and returns an unsaved draft and category options. It never invokes the import or image providers; it includes the current household favorite choices and current person ID for the draft heart control. Save through the existing recipe editor endpoint, requiring a title and persisting at least one valid category assignment. If a blank is submitted with an empty category list, the editor calls `BlankRecipeCategoryService` before opening the write transaction. The existing hosted API key and configured recipe model classify only the title and category catalog. AI chooses an existing root and a suitable existing or proposed child category; the editor saves immediately without a confirmation round trip. Manually selected categories bypass AI. Failed classification returns a retryable error without a partial save. Revision and membership checks precede classification for edits. Cooking content and nutrition are rejected for blanks. `favorite_people` contains person IDs and boolean favorite states chosen by the draft heart/dialog; these apply atomically in the viewing household for both creation and blank edits. Invalid household members roll back all changes. Older clients can still send `favorite_on_create: true`.

Existing browse, category, search, favorites, photo editing and trash operations apply. Import replaces the blank through a revision-checked update of the same ID; photo and favorite ownership remain intact. Blank share-link requests fail with 422; direct public share pages return 404. Imported recipes can be shared normally.

Run `php tests/blank_recipes.php` for disposable in-memory validation of required fields, authorization, search/category browsing, favorites, photo preservation, revision conflicts, import conversion and public sharing restrictions. The deployment workflow includes this test. Fixtures adapt MySQL locking syntax for SQLite and do not prove InnoDB concurrency semantics. No persistent local database is used.

Classifier output uses a strict JSON schema plus server validation against existing parent labels. It has no tools, no recipe content/image generation, a bounded output and request timeout, and a private per-user lock/cache to reuse the same classification after a failed save. The payload contains no favorite/member IDs, photos or household data. `php tests/blank_recipe_categories.php` checks provider payloads, malformed responses, errors and cache reuse without a live API call.

Browse accepts `blank=1` to restrict results to `source_type=blank`. `blank=0` or omission keeps all recipe types; other values and array parameters return 400. Filtering happens before pagination, intersects title/category scope and favorite filters, and bypasses category-tree/family representative grouping so every returned row is a matching blank. A converted/imported recipe leaves this filter automatically. No schema change is required.
